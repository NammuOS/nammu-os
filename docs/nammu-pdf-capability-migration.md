# Nammu PDF capability migration ledger

Source revision: the cloned `bentopdf/src/pages` tree present during PDF P2. The donor contains exactly **125 capability pages**. Its visible tool registry contains 118 unique entries; six target-size compression pages and WASM Settings are capability pages outside that registry.

This ledger is the source of truth for breadth. A capability may move to a menu, workspace, inspector, context menu, command palette, or shared operation, but it may not disappear because it is niche. At final closure every row must be `MIGRATED` and `VERIFIED`, or carry an explicit external block. `UNACCOUNTED` must remain zero.

Statuses: `NOT_STARTED`, `ENGINE_READY`, `ADAPTER_REQUIRED`, `BLOCKED_LICENSE`, `BLOCKED_RUNTIME`, `IN_PROGRESS`, `MIGRATED`, `VERIFIED`.

License shorthand: “donor AGPL” means the BentoPDF page/controller cannot be copied into Nammu without an AGPL/commercial-license decision. Named upstream libraries must be evaluated under their own licenses. “Local” means the audited implementation can operate locally once its assets are bundled; “network asset” means the donor currently obtains runtime assets from a CDN or remote service.
